# Files: one sealed store, named sets, papers as a gated kind

2026-10-20. William: explore sessions want files at the ready, e.g. a co-op employer portal
with the work term history, transcript and resume. "build out the named reusable sets".

## Target

- One store, `autobrowse files`, replaces `autobrowse papers`. Every file is sealed the same
  way papers are now (wallet Keychain key, `~/.config/autobrowse/files/`, backup to the
  same bucket, Mac and default owner only). Papers' data moves over once, then the old dir
  goes to `files-retired/` (never deleted by the code).
- Each file has a `kind`:
  - `paper`: an ID document (`--id drivers-licence --side front`, the old paper kinds).
    Same gate as now: a person says yes once per file and host, every use audited.
  - `doc`: anything else (resume, transcript, work history). No yes. Uses still audited.
- Each file has a `note` (one line: what it is, for the agent) and, for a doc, its `text`:
  read once at add time and sealed with it. PDF text by `unpdf`; DOCX by `mammoth`;
  plain text and Markdown as is; images have no text. Paper text is never kept.
- Named sets: `autobrowse files set <set> <file...>` (replace), `files sets`, `files unset`.
  A file may be in many sets. A set is a list of names in the sealed index.
- Types: today's paper types plus DOCX, TXT, MD. 12 MB max stays.

## Using them

- `autobrowse explore … --files <set>[,<set>]`: the session starts with those files. The
  explore start answer and `files` command list each one: name, kind, type, note, size.
- `upload{files:["file:<name>"]}` puts it on a page from memory (the in-memory path papers
  use). `paper:<name>` is gone; `file:<name>` of a paper runs the paper gate. A session
  without `--files` may still use any file by name (sets are a convenience, not a fence);
  a doc then needs no yes either.
- `read_file{name}`: a doc's text to the agent, for filling form fields by hand. A paper
  answers "no text: an ID document". Audited.
- Phone drop (`papers ask`) becomes `files ask <name> [--paper …]`, same Worker and link.
- Library: `autobrowse/files` export (`fileStore`, `memoryFiles`) for other projects.

## Out of scope

- Generated files (a cover letter per job): the agent writes a doc then `files add` it.
- Sharing sets between owners or machines: the box can't upload papers; docs follow the
  same Mac-only rule for now. Revisit if the box needs them.

## Decision log

- One store, not papers + a second "docs" store: one cipher, one index, one backup, one
  upload path. The gate is per kind, so ID policy stays as strict as before.
- Seal docs too: a transcript and work history are personal data. Same cost as plain.
- Text at add time, not per read: one parse, and the agent never gets the bytes.
- `unpdf` + `mammoth`: maintained, free, no native deps. No OCR for images (not needed yet).
- Break compat: `papers` CLI and `paper:` ref removed, data migrated (engineering bar).
