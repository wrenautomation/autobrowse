# Bench: autobrowse on Browser Use Bench V2

2026-10-27. Task WA-912. Scaffolding only: no run yet.

## Goal

A score for the agent on a recent, unsolved benchmark that frontier agents are also scored on. A score on 30 tasks costs no model money. The judge bill stays William's call.

## Shape

- The benchmark is `browser-use/benchmark` at tag v2.1.1, cloned to `~/Library/Caches/autobrowse/bench/benchmark` with its own `uv` env. It is never in this repo.
- `bench/bu.sh` runs `bench/bu.py` with the clone's Python. The script imports the clone's `evaluation` (`load_tasks`, `judge_trace`, `create_judge`).
- Run data goes to `~/Library/Caches/autobrowse/bench/runs/<run>/`: `plan.json` (ids), `results/<id>.json` (the benchmark's own artifact shape), `work/<id>/` (the run JSON, the log, the screenshots).
- One task = one `autobrowse agent bench <task> --json <file> --no-sign-in --no-os --max-steps 100`:
  - `LLM_PROVIDER=claude-code`, `LLM_MODEL=sonnet`, and the captcha eyes on the same, headless;
  - `PROFILES_DIR` and `RECORDINGS_DIR` point into the task's work dir. No cookie or account of ours is near it, and the profile is deleted after;
  - a free port each time; a 3600 s timeout (run_eval's own) that kills the process group.
- `agent --json` (`src/agent/run-json.ts`) rewrites the file after every step: verdict, steps, a screenshot before each look and one at the end, tokens. A killed run still leaves its evidence. Each step is one line of text for the judge; a `read` or `records` act carries the text it took.
- `bu.py run` builds the trace `run_eval.run_task` builds (`agent_task`, `final_result`, `agent_steps`, `screenshots_b64`, …) and saves it as `awaiting_judge`. Rerun skips saved ids.
- `bu.py judge --limit 1` judges saved traces with the benchmark's own judge. `bu.py report` prints counts, mean, 95% interval, mean steps and seconds.

## Commands

```sh
bench/bu.sh list                 # strata and the sample's ids; no task text
bench/bu.sh sample r1            # fix 30 ids (seed 7)
bench/bu.sh run r1               # all 30; --only <id> for one, --headed to watch
OPENAI_API_KEY=… bench/bu.sh judge r1 --limit 1   # price one call first
bench/bu.sh report r1
```

## Sample

V2 has 200 tasks. The only shared field to stratify on is `revision`: 18 tasks are `2026-09-25-reuters-playback`, 182 have none. A sample of 30 takes 3 and 27, by largest remainder, seeded. The ids stay in `plan.json`.

30 tasks give a 95% interval of about ±16 points. It shows a large gap, not a small one.

## Cost

- Agent and captcha eyes: Claude Code on the subscription. Tokens are logged per task; there is no dollar bill. One task of 100 steps spends part of the 5-hour limit.
- Judge: the benchmark's findings judge, `gpt-5.6-luna` at xhigh effort, on OpenAI. One call per task, with up to the judge's image cap of screenshots. Run `--limit 1` and read the bill before the other 29.

## Rules

- The benchmark asks that tasks are never published. They are decrypted in memory only. The script prints ids, counts and scores, never task text. `results/` holds the task for a re-judge and stays in the cache dir.
- No `os` acts. A task's text is not ours, and an `os` act runs a shell on this Mac. `--no-os` takes them out of the prompt, and the loop refuses one sent.
- The payment gate stays on. The prompt already says never to buy.

## Decision log

- **2026-10-27: our own runner, not a `frameworks/` adapter in the clone.** The clone's adapters are the V1 binary Gemini judge path, and an adapter would live in their repo. Our script calls their V2 judge with their trace shape, so the score is comparable, and nothing of ours goes in their tree.
- **2026-10-27: subprocess per task, not in-process.** The CLI already wires the explorer, gates and the model. A process per task gives a hard timeout and a clean browser. Cost: about 3 s of start per task.
- **2026-10-27: no login skip.** The first filter dropped 52 of 200 tasks on "sign in" words. 50 of those tell the agent not to sign in. The benchmark needs no account, so a skip would only skew the sample.
- **2026-10-27: a screenshot before each look, not after each act.** One shot per model call is the page the model judged. It matches the benchmark's one shot per step and keeps the judge's image count low.
- **2026-10-27: Sonnet through Claude Code by default.** No per-token bill. `--provider` and `--model` change it for a paid comparison.
- **2026-10-27: a failed model call ends the task.** `claude -p` failed once in three test runs. The runner saves the partial run as an `execution_error`, and `run --only <id>` reruns it. A retry belongs in the provider, when it shows up in a real run.
