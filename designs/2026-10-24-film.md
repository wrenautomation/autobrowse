# Film: record a run as a take (2026-10-24)

For product videos with no face and no voice. autobrowse runs the steps itself and records what
it does: each page as video, and every pointer move, click and key on the same clock. An editor
(wren's studio, or any other) then draws the cursor, the zooms and the sounds from that log.
William's ask: "really cinematic: zooms, cursor, feedback, high end sound (clicks, keyboards)".

## Decision

- Filming is a session option, not a second runner. When `AUTOBROWSE_FILM=<dir>` is set, every
  browser session autobrowse opens records itself into `<dir>`. So `agent`, `try`, a flow or a
  workflow film with no change to them.
- `autobrowse film <tape>` is the director. It opens a terminal page (ttyd) in its own Chrome,
  sets `AUTOBROWSE_FILM` for the shell, and types the tape's commands with film hands. The
  commands it types open their own browsers, and those film themselves.
- One clock: epoch ms (`Date.now()`, the same clock as Playwright's frame `timestamp`). Every pane
  and every event is on it. No offset math in the editor.
- The cursor is not filmed. The editor draws it at the render's frame rate from the log. A filmed
  cursor plays at the capture rate and cannot zoom, ripple or restyle.

## Capture

- `page.screencast.start({ onFrame, size, quality: 90 })` (Playwright 1.63, patchright the same).
  Each frame is a JPEG with its timestamp, written as it arrives.
- Sharp at 2x zoom: Chrome launches with `--force-device-scale-factor=2` and no emulated viewport.
  An emulated `deviceScaleFactor` does not reach the screencast: its frames stay at CSS size.
- Measured on this Mac (headless, 1920x1080 CSS): 2x frames (3840x2160) arrive at 30 to 35 fps
  while the page moves; 1x frames at 60 fps. Chrome sends a frame only when the page changes.
  We take 2x. The page moves at about 30 fps; the cursor, the zooms and the captions move at
  the render's 60. Scroll-heavy shots show it most.
- The window first fits the size (`fitWindow`: CDP `Browser.setWindowBounds`). Real Chrome counts
  its frame, so a 1080 window gives a 993 page. Frames of another size before the first frame of
  the final size are dropped (`settledFrames`). A later odd one is fitted inside, centred.
- One screencast per page, and its first client sets the size. So a filmed session's trace takes
  no screenshots (`Session.filmed`): the film's frames are the screenshots.
- When a session closes, ffmpeg makes `<pane>.mp4`. Each frame is on a 1/60 s slot and held until
  the next (`cfrPlan`). The concat list (`ffconcat`) names each JPEG once with its hold. The mp4 is
  VFR: only painted frames, so a still page costs nothing (a 50 s tape encodes in 3 s). `-bf 0`:
  with B-frames a held frame's dts runs ahead, and the mp4 comes out short. Then the JPEGs are
  deleted.

## Film hands

`handsFor(pace, random, record?)`: an optional sink. `play()`, `click`, `type`, `press` and
`scroll` call it. The `human/` folder still imports nothing from autobrowse. Events:

| kind | fields | from |
|---|---|---|
| `move` | t, x, y | every step of the pointer's path (`play`) |
| `down`, `up` | t, x, y | each click and drag |
| `key` | t, key | each key typed or pressed (`a`, ` `, `Enter`, `Backspace`) |
| `scroll` | t, dy | each wheel step |
| `focus` | t, box | the control a click or type acts on (x, y, w, h) |
| `load` | t, url | each main-frame navigation |

`FILM_PACE`: `HUMAN_PACE` with no slips, no wander while thinking, steady keys (about 70 ms) and a
calm reach. A person can read it at 1x.

## The take

```
<dir>/
  take.json      { version: 1, tape, size: [w, h], panes: ["term", "web-1"] }   (a tape's take)
  term.json      the terminal pane
  term.mp4
  web-1.json     each browser page, in the order they opened
  web-1.mp4
```

A pane's json: `{ name, file, kind: "web" | "term", start, end, size: [w, h], scale, events }`.
While it films it holds `filming: true`; the director waits until none does.
`start` and `end` are epoch ms. Event `t` is ms from the pane's `start`. Points are CSS px of
the page. The editor multiplies by `scale` for video px.

## Tape

```json
{ "size": [1920, 1080], "theme": "dark", "fontSize": 26, "cwd": ".", "steps": [
  { "type": "autobrowse try x-compose" },
  { "wait": "waits for your yes", "timeoutS": 120 },
  { "press": "Escape" },
  { "sleepS": 1.5 }
] }
```

`type` types the line and presses Enter. `press` presses one key. `wait` waits until the terminal
shows the text more often than it did just before the last key: only new output counts, and a
fast answer is not missed. `sleepS` holds. `size` is the terminal's; `browser` (optional) sizes each
browser the commands open, so a narrow terminal can sit beside a wide page. A tape is strict JSON (zod, `src/film/tape.ts`).

The terminal is ttyd (MIT) with xterm.js, in headless Chrome at 2x. The shell is `zsh -i` on a
clean rc: a `❯` prompt, no `%`, no right prompt. It has `AUTOBROWSE_FILM=<dir>` and
`AUTOBROWSE_FILM_SIZE=<w>x<h>`, so each command films its browser at the same size.
`autobrowse film <tape> --out <dir>` refuses a folder that holds panes.

## Needs

| tool | for | missing |
|---|---|---|
| ffmpeg | every pane's mp4 | `brew install ffmpeg` (or `FFMPEG=<path>`) |
| ttyd | a tape's terminal pane | `brew install ttyd` |

Each one is checked when `film` starts (`FILM_NEEDS`, `assertNeeds`), with the install line in the
error. `autobrowse doctor` has a `film` row: each tool ready, or its install line.

## Not chosen

- VHS: it is ttyd plus its own Chrome. It gives an mp4 but no key times, and it runs on its own
  clock. ttyd in our Chrome gives both from the recorder we already have.
- Playwright's `showActions` cursor: it draws a title box on each act, and it plays at the
  capture rate.
- OBS through obs-websocket: the whole screen, no events, and input on William's desktop.

## Pace

A filmed run uses `FILM_PACE` whatever `PACE` says (`paceFor`). Explore's hands log to the film too.

## Overlay (2026-10-28, WA-953)

A film is clean: no overlay in its frames. Each flow step goes into the pane JSON as a `step`
event (cmd, aim, ✓/✗, ms, note). An editor draws the panel from those, like the cursor.

| Option | For | Against |
|---|---|---|
| Draw it live into the frames | no edit step | at 1080p 2x its CSS loops stall acts (locator timeouts on Airbnb, Amazon); baked in for good |
| Take it off per screencast frame | live and clean | a page has one screencast; no per-frame hook |
| Rows in the JSON, drawn in the edit (chosen) | acts run as unfilmed; panel style can change after | an edit step to build |

Priorities: a run filmed must act as one unfilmed (William: "shouldn't affect the film"), then
a free choice of style later. `--overlay` still forces it live.
