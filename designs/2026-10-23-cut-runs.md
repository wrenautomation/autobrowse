# Cut one run into parts

Status: approved 2026-10-23. Building.

## Ask

One explore run on LEARN did a sign-in, read some content, a practice quiz, a real quiz and a dropbox upload. William wants that one run cut into parts: a sign-in, `dropbox-submit`, `quiz-attempt`, some read flows, and gated workflows. He wants control over the cut without hand code ("some sort of abstract domain language"). Today a person writes `learn.ts` and `uwaterloo.ts` by hand.

## Target state

1. While a person or agent drives explore, `cut <name>` marks where a part starts. The run carries the cut, so no one edits act numbers later.
2. `walks cut <run>` writes a draft cut file from the marks and the builder's guesses. A person or a model edits it. The same command builds the parts from it.
3. Each part is a walk (data, run by the one walk interpreter). The sign-in part becomes the site's `SiteLogin`. A workflow is a walk of walks.
4. Every act that worked is in the journal, `eval` and in-page downloads included. Nothing is lost.

## Recommendation: extend walks, not compile

William said "compile". The walk path fits better, so this is the trade-off said out loud.

- `compile` renders TypeScript from one recording. After render, the source is the truth. N parts would mean N TS files that new runs cannot rebuild.
- A walk is data run by one interpreter (`src/walks/flow.ts`). It already has fields, `{field}` in URLs and hints, `each` (a nested walk per row), nested `walk`, `read`, `records`, secrets by key and `irreversible`. A new run rebuilds it. Heal works per screen.
- `compile` stays for desktop and terminal recordings.

## No text DSL

A grammar means a parser and its error messages, all custom code. The cut file is JSON with a zod schema. We export JSON Schema from it, so the editor completes and checks it. That is the "domain language". Act refs accept names (cut marks), so the file reads as words, not numbers.

## The cut file

`walks/<site>/cuts/<run>.json`. Example for LEARN (act numbers are 1-based journal rows):

```json
{
  "site": "learn",
  "runs": ["20261023-135825-44fa"],
  "login": { "acts": "1-9", "credential": "uwaterloo" },
  "parts": [
    {
      "name": "dropbox-submit",
      "acts": "37-44",
      "params": { "ou": "url:ou", "db": "url:db", "file": "upload:40" },
      "gate": 43,
      "reads": [{ "after": 44, "as": "submissionId", "hints": { "text": "Submission ID" } }]
    },
    {
      "name": "quiz-attempt",
      "acts": "29-36",
      "params": { "ou": "url:ou", "qi": "url:qi" },
      "repeat": { "acts": "31-34", "over": "answers", "nth": "i" },
      "gate": 35
    },
    {
      "name": "content-read",
      "acts": "16-17",
      "reads": [{ "at": 17, "records": { "as": "items", "fields": ["title", "link"] } }]
    }
  ],
  "workflows": [{ "name": "submit-assignment", "steps": ["login", "dropbox-submit"] }]
}
```

How each of the seven needs maps:

| Need | In the cut file | New in walks |
|---|---|---|
| 1 Cut | `acts`: a range, `run:range` for several runs, or a cut mark's name | `cut` explore command journals a mark |
| 2 Params | `url:<key>` (a query value of a page it opens), `upload:<act>`, `click:<act>` (a clicked name), `typed:<act>` | field from a URL query value (today only typed values found in URLs) |
| 3 Repeats | `repeat { acts, over, nth }` | `each` gives the row index `{i}`; `nth` in hints may name a field |
| 4 Final act | `gate: <act>` | `submit: false` input: stop before the first irreversible op, return the reads so far |
| 5 Reads | `reads` with `after` / `at` an act | none (`read`, `records` exist) |
| 6 Missing acts | none for new runs; `insert` for old journals | explore journals `eval`; new `eval` and `download` walk ops |
| 7 Sign-in | `login { acts, credential }` | `walkLogin`: a `SiteLogin` that runs a sign-in walk; Duo push is a `human` wait |

Defaults the builder guesses, so most of the file is optional:
- A sign-in host (adfs, duosecurity) at the start is `login`.
- A new path family starts a part (`/dropbox/`, `/quizzing/`, `/content/`).
- A query id seen again in a later URL becomes a param.
- A click the payment or submit gate flags is the `gate`.

## Found in the code

- `eval` at `src/explore/server.ts:1744` runs with no `journal(...)` call. That is why the "My Computer" click is lost.
- `visitsOf` makes an agent's `navigate` an `open` op with the literal URL. `ou`, `db` and `qi` stay fixed today.
- `walkFromRuns` already turns an id that was typed and seen again in a URL into `{field}`. Query values that were never typed are not covered.
- `formLogin` (`src/auth/login.ts:169`) is declarative but has no Duo push step. A walk-backed login covers adfs plus Duo without a new login kind.
- The peer's act numbers (sign-in 1-8, dropbox 34-41) do not match the journal (sign-in 1-9, dropbox 37-44). That is one more reason to cut by marks, not numbers.

## Build order (after a yes)

1. Explore journals `eval` and downloads. `cut` mark command.
2. Walk ops `eval`, `download`. `{i}` in `each`. `submit: false` stop.
3. Cut file schema, `walks cut` draft and build. URL query params.
4. `walkLogin`. Workflow as a walk of walks.
5. Build LEARN from the journal. Compare with `learn.ts`.

|---|---|---|---|

| Duo push page, wrong passcode | own screens ("Other options", fail) | none | gap |

| File attached check | looks for the file name | `see` with `file: "{file}"` after Add: its base name, else stops | yes, not run live |
| Submit (gate), Yes | `submit: false` stops before Submit | same | yes |
| Done page | waits for `folder_submit_files_results.d2l` | goal screen on that URL | yes |

So `learn.ts` stays. One gap is left: the Duo branch screens. Retire `learn.ts` when the table is all yes and one live run passes.

Sign-in walks load at start (`loadDataLogins` → `walkLogins`), after the built-in and data logins, so a hand login wins (`learnLogin` stays first). A walk replaces a hand login only after a fixture test of the same screens: a push, a wrong code, a trusted device that skips Duo. A live check costs a Duo text to William and counts as the one sign-in try. Two known limits: the LEARN walk starts on a course page, and it has no `signInHere` for a wall in the middle of a session.

Looks keep the URL shape of the day they were taken. A walk is built with today's `urlShape` (`reshape`), so a rule change (the Duo id) reaches old journals.

Closed on 2026-10-23: `read` takes `match` (keep the regex's first group); `eval` takes `as` (keep the page script's answer, JSON when not text); a cut's `insert` on a load act runs on the page it opened, so a part of one load is an API read.

### Answers by option text (built)

The run clicked a checkbox whose name is the option's number. A page-wide name with a row's `nth` picks the wrong box when questions have different option counts. So a field `nth` is not enough.

Target: one op, `pick`.

```json
{ "kind": "pick", "goal": "answer question {question}",
  "region": { "css": "xpath=//h2[starts-with(normalize-space(), 'Question {question}')]/following::fieldset[1]", "frame": "…" },
  "row": "tr", "choices": "{choices}" }
```

- `region`: hints for the box that holds one question. `{field}`s fill it. Use the row's `question` field: `{i}` counts from 0 and headings count from 1.
- Options: the checkboxes and radios in the region. An option's text is its `row`'s text, read by one script that walks into shadow roots. `textContent` stops at a shadow root, and LEARN keeps option text in `d2l-html-block`. The test page puts option text in a shadow root to prove it.
- `choices`: a field, one value or a JSON list. Each must match one option's text, case and spaces aside. A choice with no option stops the walk with the options it found.
- A checkbox toggles: click only the ones that differ. A radio only turns on.
- After: read the options again with the same script. Any option not as wanted stops the walk.
- A cut makes it with what it has: `skip` the run's click and `insert` the `pick` before it, inside the `repeat`. The op's `{question}` and `{choices}` become the nested walk's fields.

Built in `src/browser/pick.ts` and `src/walks/flow.ts`; tested on a real page with option text in a shadow root (`test/walk-pick.test.ts`). Not run live: a quiz submit is William's. Two live risks: each row opens the attempt page again (D2L must keep the answers already saved), and `d2l-html-block` must render its text into its shadow root (`learn.ts` reads its `html` attribute instead).

Found while building: a look is taken before an act, and an `open` has none. So a part's end page is the page the last act landed on (`act.url`), with landmarks only from a look on that URL. A sign-in redirects after its last act (Duo, then SAML), so its end is the page the run went to next. `skip` drops acts the walk must not replay (the run's other repeat rows, a click on a dialog body).
