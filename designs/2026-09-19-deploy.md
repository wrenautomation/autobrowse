# Deploying autobrowse

Same code, three shapes. Nothing in the image is a secret; the worker
reads everything from the environment and registers itself with Restate.

## Local (today)

`pnpm worker` next to wren's local Restate (`localhost:8080/9070`), UI on
`:9080`. `.env` holds the keys. `RESTATE_ADMIN_URL` +
`RESTATE_ENDPOINT_URL` make the worker register itself; without them,
`restate deployments register http://localhost:9081` by hand.

## Docker Compose

`docker compose up --build`: Restate + worker, `.env` as `env_file`, a
volume at `/data` for profiles (logins), artifacts (traces, screenshots)
and recordings. The image is Playwright's, so `BROWSER=local` works headless
inside it; `BROWSER=browserbase` needs no Chromium at all. A headed
recording is still a laptop job (`pnpm autobrowse record`), the recording
directory is then mounted or copied in.

## AWS (built 2026-09-21, `deploy/`)

One EC2 box, not Kubernetes: one worker replica is the rule anyway (browser
profiles are per-site directories on disk), so an orchestrator buys nothing yet.

- `deploy/terraform/`: t3.medium x86 (the image is built on amd64 runners),
  16 GB root, a 20 GB gp3 `/data` volume, one SSM SecureString `/autobrowse/prod/env`
  holding the whole env as JSON, an ECR repo (last 10 images), an instance role
  that can read that one parameter and pull from ECR, a CI role over GitHub
  OIDC (wren's provider, read not created) that can push the image and run one
  command on the box. Security group: no ingress at all.
- `deploy/terraform/user-data.sh`: Docker + compose plugin, mount `/data`, write
  `/opt/autobrowse/compose.yml` (from `deploy/compose.prod.yml`) and
  `/usr/local/bin/autobrowse-deploy` (env from SSM → `/data/env/.env`, pull,
  `compose up -d`), run it once.
- `.github/workflows/deploy.yml`: after `ci` on main, build + push
  `<sha>` and `latest`, SSM RunCommand `autobrowse-deploy <sha>`, wait for it.
  Gated on repo variable `DEPLOY_ENABLED=true` so main moves before the box exists.
- Restate: the worker dials Restate Cloud's tunnel (`@restatedev/restate-sdk-tunnel`,
  in-process, no listener) when `RESTATE_TUNNEL_NAME` + `RESTATE_ENVIRONMENT_ID`
  + `RESTATE_CLOUD_REGION` + `RESTATE_IDENTITY_KEY` are set, then registers the
  tunnel's deployment URL against the env's admin API itself. `src/app/endpoint.ts`
  is the decision (pure, tested); a half-set tunnel refuses to start rather than
  silently listening. Without those, the plain listener, now also honouring
  `RESTATE_IDENTITY_KEY` for a public endpoint.
- Secrets: the env store, SSM `/autobrowse/config/<NAME>` (one SecureString
  each; KMS at rest, IAM at the door, reads in CloudTrail). `autobrowse env
  push --from deploy/prod.env` (or named keys from `.env`) writes it from a
  laptop; the worker's `keep` writes it in prod; `deploy/scripts/on-box-deploy.sh`
  (shipped by CI before every run) reads it into `/data/env/.env`. `autobrowse
  env pull|get` brings values back to any machine: clipboard (cleared after a
  minute), `export` lines, or a 0600 env file. Names print, values never.
- Reach: UI on the box's loopback, SSM port forwarding from a laptop (terraform
  output `ui_forward`); shell via SSM Session Manager; no SSH, no public port.
- Applied 2026-09-21 (William's call: cheaper, not always on). The box is **stopped
  between jobs**: $0 stopped, ~$2/month volume, ~$1/day running. `deploy/scripts/box.sh
  start|stop|status`; the deploy workflow starts it, ships, and re-stops it. A worker
  that must run while the laptop sleeps starts the box itself (next: a `box start`
  effect before a scheduled run, `stop` after the queue drains).
- `aws login` and `restate cloud login` were both completed through autobrowse explore
  sessions on 2026-09-21 (device-code flows: the page is signed in from stored
  credentials, the code is read off the page and fed to the waiting CLI).
- Kubernetes later, if ever: the same image; `restate-operator` injects the
  `RESTATE_INPROC_*` variables the tunnel SDK reads, so the endpoint code needs nothing.

## What is not containerized

Headed recording and site logins: a person does them once on a machine
with a screen. Everything after (`compile`, runs, gates) runs anywhere.
