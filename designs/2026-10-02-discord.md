# Discord site (2026-10-02)

William: autobrowse should sign in to Discord, set up his server, ideally
through API tokens. Lander intake, SMS and email pings each get their own
channel.

## Shape

- Sign-in: `discord` login spec (`src/auth/sites.ts`): email + password,
  hCaptcha solved by the runner (`formLogin` gained `captcha`), TOTP when 2FA
  is on. A "new login location" email link is a person's.
- Bot, not user token: `setup discord bot-token` mints an application + bot
  on the developer portal and keeps `DISCORD_APP_ID`, `DISCORD_BOT_TOKEN`;
  `setup discord invite` is the one consent that adds it to the server.
  Using the user's own token from the browser is self-botting (against
  Discord's terms) and would die with every sign-out.
- Everything else is REST (`src/sites/discord.ts`): servers, channels
  (make, rename, move, delete), webhooks.
- Bot permissions: view, send, manage channels, roles, webhooks. Not
  Administrator: a leaked token cannot ban members or delete the server.
- A webhook URL authorises posting, so it is a secret: `POST
  /channels/{id}/webhooks` takes `keep` (an env name) and puts the URL in the
  sink; answers never carry a token (`ApiLeg.keep`).

## Layout: data apart per sales channel

William: "clear data segregation for different sales channels". One category
per group, one channel per lane, one webhook per channel. wren reads each
lane's URL (`WREN_DISCORD_<LANE>_WEBHOOK_URL`, unset = the main one).

| Category | Channel | Who posts | Secret |
|---|---|---|---|
| Outbound | email | send, inbox, compose, warm replies | `WREN_DISCORD_EMAIL_WEBHOOK_URL` |
| Outbound | sms | SMS loops | `WREN_DISCORD_SMS_WEBHOOK_URL` |
| Outbound | reach | Reddit/LinkedIn DMs | `WREN_DISCORD_REACH_WEBHOOK_URL` |
| Inbound | intake | lander form | `LANDER_DISCORD_WEBHOOK` → lander `DISCORD_WEBHOOK` |
| Inbound | search | SearchWatch/Week | `WREN_DISCORD_SEARCH_WEBHOOK_URL` |
| Marketing | ads | AdsWatch | `WREN_DISCORD_ADS_WEBHOOK_URL` |
| Marketing | content | content loops | `WREN_DISCORD_CONTENT_WEBHOOK_URL` |
| Clients | clients | delivery, reactivation | `WREN_DISCORD_CLIENTS_WEBHOOK_URL` |
| Ops | ops | digest, token renewal, audit seals | `WREN_DISCORD_WEBHOOK_URL` |

`PUT /guilds/{id}/layout` (autobrowse's own path) applies it: makes what is
missing, moves a same-named channel under its category, sets topics, makes
one `Wren` webhook per channel and keeps every URL. Idempotent; never
deletes; lists channels it left alone. Bot avatar and server icon: `PATCH
/users/@me {avatar}`, `PATCH /guilds/{id} {icon}` from a path or URL (the
rust pfp, `lander/public/brand/wren-pfp.png`).
