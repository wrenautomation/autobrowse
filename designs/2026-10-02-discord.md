# Discord site (2026-10-02)

William: autobrowse should sign in to Discord, set up his server, ideally
through API tokens. Lander intake, SMS and email pings each get their own
channel.

## Shape

- Sign-in: `discord` login spec (`src/auth/sites.ts`): email + password,
  hCaptcha solved by the runner (`formLogin` gained `captcha`), TOTP when 2FA
  is on. A "new login location" email link is a person's.
- Bot, not user token: `setup discord bot-token` mints an application + bot
  on the developer portal and keeps `DISCORD_APP_ID`, `DISCORD_BOT_TOKEN`;
  `setup discord invite` is the one consent that adds it to the server.
  Using the user's own token from the browser is self-botting (against
  Discord's terms) and would die with every sign-out.
- Everything else is REST (`src/sites/discord.ts`): servers, channels
  (make, rename, move, delete), webhooks.
- Bot permissions: view, send, manage channels, roles, webhooks. Not
  Administrator: a leaked token cannot ban members or delete the server.
- A webhook URL authorises posting, so it is a secret: `POST
  /channels/{id}/webhooks` takes `keep` (an env name) and puts the URL in the
  sink; answers never carry a token (`ApiLeg.keep`).

## Channels

| Channel | Who posts | Secret |
|---|---|---|
| email | wren worker (replies, bounces, digest, everything else) | `WREN_DISCORD_WEBHOOK_URL` |
| sms | wren SMS loops | `WREN_DISCORD_SMS_WEBHOOK_URL` (unset = email's) |
| intake | lander form | lander `DISCORD_WEBHOOK` |
